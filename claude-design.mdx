Claude Design може збирати макети з цієї дизайн-системи — але тільки якщо дати йому систему у зрозумілому вигляді. Ця сторінка пояснює, як саме.

Уся документація — це майже 60 сторінок української прози з поясненнями й прикладами. Генератору потрібне інше: **точні значення й розмітка**, без пояснень. Для цього є окремий файл, зібраний скриптом із `tokens.json`, `style.css` і самих сторінок.

Найбільший розділ — дев'ятий, він займає майже весь файл. Для кожного компонента там **точна розмітка** і **всі CSS-правила**, причому змінні розгорнуті в реальні значення: не `var(--color-action-primary)`, а `#000000ff` з іменем змінної в коментарі.

Саме цього бракувало раніше. Без розділу 9 генератор знав, що хедер існує, але не знав, що в ньому всередині — і малював власний.

Два останні розділи не менш важливі. Без них модель вигадає брейкпоінти й анімації, яких у системі не існує, або візьме зіпсовані значення з експорту Figma.

<Warning>
  Файл великий — приблизно 38 тисяч токенів. Це свідомий вибір: стислий переказ дає стислий результат. Якщо ваш інструмент не приймає такий обсяг, скажіть — зробимо версію без розділу 9, але тоді точність впаде до рівня «схоже на ваш дизайн».
</Warning>

## Крок 2. Додайте його в Claude Design

Покладіть файл у контекст проєкту — туди, звідки Claude Design читає матеріали. Він має бути доступний у кожному запиті, а не тільки в першому.

<Warning>
  Точне місце в інтерфейсі залежить від версії Claude Design. Якщо там є окреме поле для дизайн-системи — файл туди; якщо ні, вставте його текстом на початку промпту.
</Warning>

## Крок 3. Напишіть промпт

Після файлу додайте це:

```text
You are designing a page for Lazarev.agency using their design system.
The complete system specification is above. Follow it exactly.

Rules:
- Use only components from section 9. Reproduce their markup and styles exactly.
- Use only colours and type styles listed in the specification.
- Desktop canvas 1440px, container 1344px, 48px side padding.
- Every block carries 220px top padding. No bottom padding.
- Section title to content: 56px.
- First block leaves 88px for the fixed header.
- Every section starts with a Title block (title, description, optional button).
- Every page ends with the Footer. Never omit it.
- Breadcrumbs are always centred in the container, never flush left.
- If a value you need is not in the specification, say so instead of inventing it.
  Section 10 lists what genuinely does not exist in this system.

Task:
```

Далі опишіть сторінку звичайною мовою. Українською теж можна — назви компонентів у файлі англійські, і модель їх упізнає.

> Сторінка послуги: герой із заголовком і кнопкою, три кейси, блок процесу на сім кроків, FAQ, CTA.

## Крок 4. Перевірте на одній секції

Не починайте з цілої сторінки. Попросіть **одну секцію** — наприклад, блок із трьома кейс-картками під заголовком.

Далі перевірте три числа:

<div className="ds-table">

| Що | Має бути |
| --- | --- |
| Відступ згори в блоку | 220px |
| Від заголовка до карток | 56px |
| Ширина картки кейсу | 312px |

</div>

Далі порівняйте розмітку з розділом 9. Якщо класи збігаються — генератор читає специфікацію, а не вигадує свою структуру.

Якщо всі три збіглися — система читається, можна просити цілу сторінку. Якщо ні, буде видно, чого саме бракує.

## Як просити зміни

Посилайтесь на компоненти їхніми іменами з інвентарю — так само, як вони називаються в цій документації.

<Check>
  «Заміни Secondary button на Primary», «постав Case card розміру L замість S», «додай Title block над цією секцією».
</Check>

<Warning>
  Не описуйте компонент словами, якщо він є в системі. «Зроби картку з картинкою і заголовком» дасть вигадану картку замість [Case](/cards/case).
</Warning>

Це перелічено і в самому файлі, але варто знати заздалегідь — просити це марно:

| --- | --- |

| Теми | Світлої й темної теми в токенах немає |

</div>

## Як оновити файл

Файл не пишеться руками — його збирає скрипт із репозиторію:

```bash
python3 scripts/build-brief.py
```

Він читає `tokens.json`, `style.css`, `docs.json` і `scripts/brief-inventory.json`, а на виході дає два однакові файли: `system-brief.md` для читання в репозиторії та `assets/lazarev-design-system.txt` для завантаження з цієї сторінки.

Коли ви описуєте новий компонент, допишіть йому один рядок у `scripts/brief-inventory.json`:

```json
{ "page": "blocks/hero", "title": "Hero", "class": "ds-hero", "purpose": "Home page hero with stats and illustration" }
```
